# Self-hosted production target

The user selected a self-hosted reference stack. The executable [integration composition](../integration/compose.yaml) now runs actual PostgreSQL, Keycloak, OpenBao transit, S3-compatible objects, ClamAV and WordPress/MariaDB with pinned images. Follow the [reference guide](../../docs/operations/self-hosted-reference.md) to reproduce it. It uses synthetic identities, dev-mode services, loopback HTTP, disposable storage and broader S3 fixture permissions; it is not a production deployment manifest.

`local`, `integration` and restricted `staging` profiles exist; `production` still rejects startup. Staging requires independently authenticated identity, PostgreSQL with verified TLS, external keys/objects/scanner, HTTPS service URLs and a non-root process. These are configuration guards, not verified infrastructure approval. Do not use staging to bypass the release decision.

Actual persistent/sealed HA key and identity services, ingress/TLS, object IAM/WORM/durability, independent immutable audit, coordinated managed backups/current-policy recovery, monitoring, capacity/failover evidence, signed delivery and the unfinished product/client requirements remain. The [production exit criteria](../../docs/release/production-exit-criteria.md) describe the dependency order and independent human evidence. No customer domain, jurisdiction, service identity, signing authority, operational SLA or production signatory was invented.
